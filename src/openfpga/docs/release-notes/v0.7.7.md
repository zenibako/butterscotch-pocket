# v0.7.7 — upstream compatibility and Memories repair

**Draft for device testing.** Automated checks pass on the release base. The final public package still needs the Pocket checks listed below before stable publication.

## Changes since v0.7.6

- **Memories:** repairs the renderer-layout mismatch introduced by the upstream update. Both original and expanded revision-9 snapshots are recognized, with identity, checksum and resource validation retained. New captures use revision 10 and store renderer settings without saving renderer pointers. See [PR #64](https://github.com/zenibako/butterscotch-pocket/pull/64).
- **Rendering:** corrects equal-depth layer ordering and prevents fractional nine-slice drawing from stalling. Repeated room-layer lookups do less work; no new Pocket frame-rate measurement is claimed.
- **Engine compatibility:** incorporates Butterscotch updates through [`70b80134`](https://github.com/ButterscotchRunner/Butterscotch/commit/70b801344f0a8606f03c14bf1d0bf4ac9b4a2416), including VM, variable and script-argument fixes and additional builtins. The new `struct_get`/`struct_set` functions include argument-count and temporary-string lifetime repairs.
- **Distribution:** runner, Pocket port, preparation tools and plugin now build from one repository and source commit. The installed core also recommends its companion Pocket Sync preparation plugin. Each release continues to include both game programs, the plugin/icon, six native preparation bundles, WASI CLI, source archives, licenses, provenance and checksums.

## Installation and Memory compatibility

Import [butterscotch-pocket.zip](https://github.com/zenibako/butterscotch-pocket/releases/download/v0.7.7/butterscotch-pocket.zip) in Pocket Sync, or extract it into the SD-card root, merging `Cores`, `Assets` and `Platforms` and replacing matching files. Install the complete core package so the programs and runtime remain matched.

Supply your own **Undertale v1.08** or **Deltarune Chapter 1** data. Existing prepared game data does not need conversion for this update. New installations can follow [GAME-DATA.md](https://github.com/zenibako/butterscotch-pocket/releases/download/v0.7.7/GAME-DATA.md). Additional games, versions and chapters are not newly supported.

Back up the card and preserve game files, `/Saves/butterscotch/common/` and Memories. No commercial game data or player saves are included. Ordinary progress saves remain separate from Memories and sleep snapshots.

- Snapshot revisions 3–9 remain readable when their game identity and resources match. Use the original game data; compatibility is not guaranteed for every historical Memory.
- New revision-10 Memories require an updated core and cannot be loaded by older builds.
- **Private test builds:** public programs omit private compile-time whole-file fingerprints. A Memory from a personal build may therefore still be rejected by this public package. The renderer-layout repair does not remove identity checks or convert private-build Memories.

## Known limitations

- Deltarune battle Memories can load with party and enemy sprites missing. This release does not fix [issue #61](https://github.com/zenibako/butterscotch-pocket/issues/61).
- Memories and sleep/wake remain experimental and scene-dependent. Check **Select > Debug > Save-state status** before sleeping.
- The SDK, runtime/API and compiler pins are unchanged from v0.7.6: SDK base `a408ddc1`, runtime `902a8adc`, GCC 13.2.0. The 100 MHz os25 runtime retains **−0.777 ns worst setup slack** in the slow 85°C timing corner; it is not a timing-clean FPGA build.
