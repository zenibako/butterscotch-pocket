# v0.7.12 — smoother battles and sharper Speed mode

Undertale v1.08 and experimental Deltarune Chapter 1 remain the supported games.

## What's new

- **Undertale battles start more smoothly.** Battle artwork, dialogue fonts and voices, and common sounds load ahead of time, reducing pauses at battle start and the first enemy speech bubble while keeping the heart animation at its normal pace. This covers ordinary encounters and story battles. Assets that cannot finish in advance still load when needed. [PR #110](https://github.com/zenibako/butterscotch-pocket/pull/110) · [PR #113](https://github.com/zenibako/butterscotch-pocket/pull/113)
- **Most Undertale battles look sharper in Speed mode.** They now draw at 640×480; the heaviest battles, including Photoshop Flowey and Mettaton NEO, stay at 320×240. Deltarune's Speed battles remain at 320×240. [PR #109](https://github.com/zenibako/butterscotch-pocket/pull/109)
- **Heavy battles draw faster.** The renderer avoids unnecessary work on transparent parts of rotated sprites and on large fills. Speed mode also handles late frames better, including more flexible frame skipping during Photoshop Flowey's fight after its intro. [PR #109](https://github.com/zenibako/butterscotch-pocket/pull/109)
- **Asgore and Deltarune get further performance improvements.** Movement and Asgore's orange fire particles do less repeated calculation. Deltarune's tile layers reuse more rendering work, and repeated battle-grid rows draw more efficiently. [PR #106](https://github.com/zenibako/butterscotch-pocket/pull/106) · [PR #112](https://github.com/zenibako/butterscotch-pocket/pull/112)
- **Deltarune’s field draws faster while the camera is still.** The renderer reuses the composed tile layers and redraws only the areas changed by later draws. [PR #122](https://github.com/zenibako/butterscotch-pocket/pull/122)
- **Tinted sprites draw faster in Deltarune battles.** The renderer applies the tint once per source pixel for eligible sprites drawn at double size. [PR #123](https://github.com/zenibako/butterscotch-pocket/pull/123)
- **Collision checks do less repeated work.** Butterscotch's upstream runner now caches instance bounding boxes and checks rectangle collisions without copying the instance list. [PR #126](https://github.com/zenibako/butterscotch-pocket/pull/126)
- **Reports can be read from a phone photo.** Finished benchmarks display a QR code of their report; any button switches between the code and the log. Fatal errors show the log first, with a QR code of its end available. Oversized reports are marked as shortened; the file on the card keeps the full log. [PR #107](https://github.com/zenibako/butterscotch-pocket/pull/107) · [PR #108](https://github.com/zenibako/butterscotch-pocket/pull/108)

- **Performance Mode is selected from the menu.** Use Select → Performance Mode to choose Speed or Accuracy; L no longer changes it. The opening instructions now point to the Butterscotch menu. Select and Start prompts show the leftmost and rightmost of the three small circular buttons. [PR #116](https://github.com/zenibako/butterscotch-pocket/pull/116)

## Diagnostics and fixes

- Battle and bullet-hell tours can measure live Speed pacing. Reports separate gameplay updates, pictures displayed, skipped draws and stalls; battle tours can also target a chosen list of encounters. Read logs and prefetch counters help locate remaining loading pauses. The slow-frame logging threshold can be set with `--slow-frame-ms`. [PR #109](https://github.com/zenibako/butterscotch-pocket/pull/109) · [PR #110](https://github.com/zenibako/butterscotch-pocket/pull/110) · [PR #113](https://github.com/zenibako/butterscotch-pocket/pull/113)
- QR reports can be decoded with `src/openfpga/tools/pq1-decode.py`. Benchmark documentation now explains how to collect and interpret them. [PR #107](https://github.com/zenibako/butterscotch-pocket/pull/107) · [PR #108](https://github.com/zenibako/butterscotch-pocket/pull/108)
- Restoring a Memory selects the battle's drawing size again. Background preloading also hands off safely before lazy room and fallback texture reads, including builds without native save states. Invalid slow-frame arguments no longer consume a following option. [PR #109](https://github.com/zenibako/butterscotch-pocket/pull/109) · [PR #113](https://github.com/zenibako/butterscotch-pocket/pull/113) · [PR #114](https://github.com/zenibako/butterscotch-pocket/pull/114)
- Deltarune's Bloxer battle no longer slows to about one frame per second while choosing HEAD, BODY or LEGS. Its selection arrow is drawn 1 pixel wide again instead of as a huge bar. [PR #125](https://github.com/zenibako/butterscotch-pocket/pull/125)
- The webOS build authenticates its CLI release lookup to avoid unauthenticated GitHub API rate limits. [PR #113](https://github.com/zenibako/butterscotch-pocket/pull/113)

## Installing and known issues

Import the core ZIP in Pocket Sync, or extract it to the root of your SD card, merging the `Cores`, `Assets` and `Platforms` folders. Existing prepared game data and ordinary progress saves can be reused.

Some heavy scenes still slow down, and preloading does not eliminate every loading pause. Memories and sleep/wake remain experimental; Deltarune battle Memories can restore with missing party or enemy sprites. [Issue #61](https://github.com/zenibako/butterscotch-pocket/issues/61)
