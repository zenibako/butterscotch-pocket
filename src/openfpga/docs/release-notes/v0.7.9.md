# v0.7.9 — upstream Butterscotch update

Brings in upstream Butterscotch changes through [`16cc6519`](https://github.com/ButterscotchRunner/Butterscotch/commit/16cc6519). Undertale v1.08 and Deltarune Chapter 1 remain the supported games.

## Changes since v0.7.8

- **Engine compatibility:** adds GameMaker sequences (SEQN chunk and runtime; `layer_destroy` also removes sequence elements), the matrix stack, `date_second_span`, `game_id`, `texturegroup_get_textures` and placeholder substitution in `string()`. See [PR #72](https://github.com/zenibako/butterscotch-pocket/pull/72).
- **Fixes from upstream:** nine-slice mirror and flip drawing, call-frame regressions, `with` no longer destroying unrelated instances, collision checks, text wrapping, and the TGIN texture-group chunk read on its own instead of from TXTR.
- **Image decoding:** includes upstream's faster QOI decoder ([PR #71](https://github.com/zenibako/butterscotch-pocket/pull/71)). Upstream's wuffs image decoder was reverted because it broke bzip2 texture pages, so Pocket builds keep the stb decoder.
- **Performance fix:** upstream's collision-order change sorted the list of collision objects on every step, which cost Undertale about 3.4 ms per frame on the Pocket. The list is now sorted once at load, so both games run at v0.7.8 speed ([PR #73](https://github.com/zenibako/butterscotch-pocket/pull/73)).
- **Pocket port:** the log overlay keeps its existing font, and upstream's new 512×512 default font is left out of the Pocket programs.

## Installation and Memory compatibility

Import [butterscotch-pocket.zip](https://github.com/zenibako/butterscotch-pocket/releases/download/v0.7.9/butterscotch-pocket.zip) in Pocket Sync, or extract it into the SD-card root, merging `Cores`, `Assets` and `Platforms`. Existing prepared game data, ordinary saves and Memories stay in place, and prepared data does not need converting. New installations can follow [GAME-DATA.md](https://github.com/zenibako/butterscotch-pocket/releases/download/v0.7.9/GAME-DATA.md).

The Memory format stays at revision 10. The one new instance field fits in existing padding, so the saved layout is unchanged and v0.7.8 Memories should load. Sequence state is not saved in Memories; neither supported game uses sequences.

## Verification

Both Pocket programs build with the pinned compiler, and complete distribution CI checks both public game builds, native tools, plugin/C-reference behavior, snapshot tests, packaging and checksums.

## Known limitations

- Every game load now parses the SEQN chunk. Games with sequences use more heap at load time, and an unexpected SEQN version stops the load with an error instead of skipping the chunk.
- Deltarune battle Memories can load with party and enemy sprites missing ([issue #61](https://github.com/zenibako/butterscotch-pocket/issues/61)).
- Memories and sleep/wake remain experimental and scene-dependent. Check **Select > Debug > Save-state status** before sleeping.
- The SDK, runtime/API and compiler pins are unchanged from v0.7.8: SDK base `a408ddc1`, runtime `902a8adc`, GCC 13.2.0. The 100 MHz os25 runtime retains **−0.777 ns worst setup slack** in the slow 85°C timing corner; it is not a timing-clean FPGA build.
